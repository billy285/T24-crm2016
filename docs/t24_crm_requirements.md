# T24 CRM 内部客户管理系统需求说明（V1.0）

> 目标：在**不推翻现有可用功能**的前提下，持续修复与完善，形成稳定的内部 CRM + 业务协同系统。

## 1. 项目边界与定位

- 系统类型：单公司内部使用系统（非多租户 SaaS）。
- 使用对象：销售、运营、设计、财务、人事、管理员、老板。
- 核心原则：
  1. 不做大范围重构，优先在现有系统上补齐短板。
  2. 页面、业务逻辑、数据接口分层清晰。
  3. 读写权限一致（可见即有对应权限判定，不出现“能看不能改”的混乱状态）。
  4. 数据稳定、关系清晰、长期可维护。

## 2. 业务目标

1. 销售可管理客户与销售跟进。
2. 运营可管理客户服务与工作记录。
3. 财务可管理收入、支出、续费及经营数据。
4. 管理员可管理人员、权限和系统设置。
5. 老板可通过仪表盘查看经营情况。

## 3. 角色与权限模型（RBAC）

系统角色（固定枚举）：

- `super_admin`（超级管理员）
- `admin`（管理员）
- `sales`（销售）
- `operations`（运营）
- `designer`（设计）
- `finance`（财务）
- `hr`（人事）
- `boss`（老板/经营查看）

### 3.1 登录与认证

- 支持账号/邮箱 + 密码登录。
- 支持退出登录。
- 记录最后登录时间。
- 记录登录日志（成功/失败、IP、UA、时间）。

### 3.2 菜单可见性（登录后）

#### super_admin / admin
可访问：
- 仪表盘
- 客户管理
- 销售跟进
- 成交管理
- 服务进度
- 运营记录
- 财务管理
- 员工管理
- 系统设置
- 权限设置
- 操作日志

#### sales
可访问：
- 仪表盘（销售视角）
- 客户管理（本人/授权范围）
- 销售跟进
- 成交管理（发起、查看、更新状态）
- 个人工作台

#### operations
可访问：
- 仪表盘（运营视角）
- 客户服务进度
- 运营记录
- 协同任务（与销售/设计协作）

#### designer
可访问：
- 服务任务（设计相关）
- 交付记录
- 返修记录

#### finance
可访问：
- 财务管理（收入、支出、续费）
- 开票/回款状态
- 财务报表

#### hr
可访问：
- 员工管理（档案、状态、岗位）
- 组织与角色分配（按授权范围）

#### boss
可访问：
- 经营仪表盘（只读）
- 业务汇总报表（只读、可导出）
- 核心预警（应收逾期、项目延期、续费到期）

### 3.3 权限控制要求

- 采用“模块 + 动作”粒度：`view/create/edit/delete/export/audit`。
- 每个接口必须做后端权限校验，前端仅做体验层隐藏。
- `boss` 默认仅授予 `view/export`，不授予新增、编辑、删除权限。
- 数据级权限：
  - 销售默认仅看本人客户；可按规则共享。
  - 运营可看被分配服务单。
  - 财务可看全部财务数据，不可修改客户核心资料（除账务字段）。
- 权限变更需写操作日志。

## 4. 功能模块需求

## 4.1 仪表盘（老板/管理层）

- 核心指标：新增客户数、跟进次数、成交额、回款额、续费率、毛利、应收未收。
- 支持按时间筛选（日/周/月/季度/自定义）。
- 支持按团队/员工维度下钻。
- 图表数据可导出。

## 4.2 客户管理

客户主档字段建议：
- 客户编号（唯一）
- 客户名称
- 联系人、电话、邮箱
- 行业、地区、来源渠道
- 客户等级、状态（潜在/跟进中/成交/停用）
- 负责人（销售）
- 创建时间、更新时间

核心能力：
- 列表：搜索、筛选、分页、导出。
- 新建/编辑/归档。
- 客户查重（名称 + 电话/邮箱规则）。
- 客户转移（需记录审批/日志）。
- 客户详情页聚合：跟进、成交、服务、财务记录。

## 4.3 销售跟进

跟进记录字段：
- 跟进方式（电话/微信/拜访/邮件）
- 跟进内容
- 下次跟进时间
- 当前阶段（初访/报价/谈判/待签约）
- 跟进人

要求：
- 每次跟进必须关联客户。
- 支持提醒（即将到期/逾期）。
- 支持查看跟进时间线。
- 跟进记录不可物理删除（仅可作废并留痕）。

## 4.4 成交管理

- 记录成交信息：合同编号、合同金额、币种、签约日期、服务周期、负责人。
- 支持阶段：待审核 → 已生效 → 履约中 → 已完结/已终止。
- 成交自动联动：
  - 客户状态更新为“成交”；
  - 生成服务任务；
  - 通知财务建立回款计划。

## 4.5 服务进度 / 运营记录

服务任务字段：
- 任务编号、客户、项目类型、开始/截止时间、负责人、协作者、状态、优先级。

功能：
- 任务看板（待开始/进行中/待验收/已完成）。
- 运营日报/周报。
- 关键节点留痕与附件。
- 延期原因记录与预警。

## 4.6 财务管理

范围：收入、支出、续费、应收应付。

关键规则：
- 所有金额必须带币种（如 CNY/USD）。
- 汇总报表要明确统计口径（含税/未税）。
- 记录回款计划、实际回款、发票状态。
- 支持按客户、时间、项目、负责人筛选。
- 支持导出对账数据。

## 4.7 员工管理

- 员工档案：姓名、账号、角色、部门、状态（在职/离职/停用）。
- 支持重置密码、停用账号。
- 角色授权与数据范围配置。
- 员工变更记录（岗位/角色/状态）留痕。

## 4.8 系统设置

- 基础字典（行业、客户来源、任务类型、费用分类）。
- 编号规则（客户编号、合同编号、服务单号）。
- 通知配置（站内信/邮件）。
- 数据备份与恢复策略（至少具备导出备份能力）。

## 4.9 操作日志

日志记录范围：
- 登录/登出
- 新建/编辑/删除/导出
- 权限变更
- 财务数据修改

日志字段：
- 操作人、角色、模块、动作、对象ID、变更前后摘要、IP、时间。

要求：
- 管理员可查询日志。
- 支持按时间、人员、模块筛选。
- 日志不可被普通角色删除。

## 5. 列表页统一规范（全系统）

所有列表页必须具备：
- 关键词搜索
- 多条件筛选
- 分页
- 排序
- 导出（按权限）
- 列表与详情跳转一致

## 6. 数据一致性与联动规则

- 客户删除策略：默认软删除或归档，禁止直接硬删除核心业务数据。
- 客户与成交/服务/财务为强关联，禁止产生孤儿数据。
- 成交生效后必须可追溯对应回款计划与服务任务。
- 员工停用后不影响历史数据归属，但禁止继续操作。

## 7. 技术实现约束（延续现有系统）

- 优先修复已有模块，不做大规模推翻。
- 避免“自动 CRUD 直出页面”导致业务规则缺失。
- 推荐分层：
  - 表现层（页面/组件）
  - 应用层（用例/流程编排）
  - 领域层（业务规则）
  - 数据层（DAO/Repository）
- API 需版本化并保持向后兼容（如 `/api/v1/...`）。

## 8. 迭代优先级（建议）

### P0（必须先完成）
1. 登录、角色权限、菜单与接口权限统一。
2. 客户管理 + 销售跟进主流程可用。
3. 成交后服务/财务联动打通。
4. 财务金额与币种统一、关键报表可导出。
5. 操作日志全链路落地。

### P1（第二阶段）
1. 仪表盘多维统计与下钻。
2. 服务进度看板与延期预警。
3. 员工管理与组织权限细化。

### P2（持续优化）
1. 表单体验优化与批量操作。
2. 高级报表与自定义统计。
3. 审批流（客户转移、折扣、退款等）。

## 9. 验收标准

- 权限：不同角色登录后菜单、接口、数据范围一致。
- 稳定：关键流程（客户→跟进→成交→服务→回款）无断链。
- 正确：金额、币种、状态流转、统计口径准确。
- 可用：列表检索/筛选/分页/导出齐全。
- 可追溯：关键操作可在日志中还原。

## 10. 给 AI 的执行约束（开发时）

1. 优先改“错”和“缺”，谨慎改“结构”。
2. 一次提交只解决一类问题，避免大杂烩修改。
3. 改动前先确认涉及角色和数据联动。
4. 每个新增功能必须包含权限校验与日志记录。
5. 提交说明必须写清：改了什么、影响什么、如何验证。
